# Session metrics — Phase 2 implementation slice

## Implemented

- `engine/session_metrics.go`: optional execution-owned accounting initialized for newly observed executions, with legacy records left untouched. Settlement/restart downgrades any complete amount on a non-completed execution. Existing duration/outcome behavior is unchanged.
- `engine/session_metrics_accounting.go`: separate Pi cumulative baseline/endpoint evidence and recomputed execution deltas. Evidence includes RPC key, observation timestamp, native ID/path, uncached input/output and cache read/write counters. Execution input includes both cache categories; output is not augmented by reasoning. Reasoning remains null because statistics do not provide its breakdown. Model allocation remains unavailable.
- `engine/pi_interactive.go`: after required native state validation, a correlated pre-prompt statistics barrier resolves before prompting. Baseline and final response waits each have a 2 s budget, starting after `proc.Send` returns successfully. A baseline timeout/write failure releases prompting, without treating any later snapshot as zero/history baseline. Normal settlement requests a distinct final snapshot rather than treating a prior in-turn read as final. Interim requests do not introduce a response wait or delay settlement.
- Stats RPC requests reuse the existing `proc.Send` transport exactly as before this slice. The newly introduced `SendOptional` method and its unused `os` import were removed from `engine/interactive.go`, restoring that file to its prior behavior. There is no pipe-deadline support requirement, goroutine, transport redesign, or bounded-write guarantee: `Send` retains its existing synchronous mutex/encoder behavior. Returned write failures remain optional accounting gaps (`baseline_request_write_failed` / `final_request_write_failed`), not execution errors.

Repeated responses are accepted only for the currently correlated request; repeated endpoint observations replace, never add. Every delta is recalculated against the one observed pre-prompt baseline. Native ID **and** normalized absolute file path must match. Invalid/missing/overflowing counters, a reported total inconsistency, identity mismatch or observed decrease invalidates the segment and clears its amount, retaining the first failure reason. No resumed lifetime snapshot is subtracted blindly. Final timeout/exit leaves any proven interim amount partial; absent evidence stays null. This does not prove exclusive parent usage or per-model attribution.

Accounting is persisted using existing owning-session `commitLocked` transactions at observations and adapter exit, then settles in the existing execution transaction. There is no separate ledger, backfill, API, frontend or status-bar schema change. Normal storage failures retain the engine's existing essential fail-closed policy; optional telemetry errors themselves are not returned as execution errors. Existing `Session.Usage`, its normalizers and rendering are untouched. Correlated lifetime stats responses still use the existing path gate and normalization. Stats requests are no longer skipped on Windows pipes lacking write-deadline support, preserving the existing status-bar transport behavior.

## Money and version evidence

All execution costs are explicitly null, with `costReason=currency_provenance_not_verified_for_runtime`. There is no monetary arithmetic, price lookup, estimate service or subscription billing claim. Pi's package version is recorded from launch-package metadata when accessible; that is not a newly verified currency/provenance contract for managed Pi 0.85.1, nor proof of an already retained process's version after package replacement. Inspected Pi 1.4.0 monetary capabilities are not assumed to apply to the managed runtime.

## Deliberate omissions / remaining work

- OpenCode V1/V2 accounting is not instrumented. Existing baseline/final history processing is left unchanged: its final walk can stop at the first baseline message and does not prove the complete inventory/removal/correction checks required for trustworthy accounting. Extending it safely needs a bounded, complete native inventory and separate keyed message/step ledger; cost remains unverified.
- Codex execution usage is explicitly unavailable (`trustworthy_boundary_baseline_unavailable`); no subtraction of its status-bar totals or summation of repeated `last` snapshots.
- No execution-usage aggregates, API projection changes, dashboard rendering, period/trend attribution, model segments, delegated sums, timing or retry collection.
- Human validation remains needed for normal multi-turn/resumed Pi execution, lifetime/status-bar refresh on Windows, repeated snapshots, cache categories, malformed/missing counters, identity/reset handling, final timeout, cancellation and restart persistence. No live prompts/user data were exercised here. Pipe write-deadline support is not a prerequisite; writes retain the existing `Send` contract.

## Lightweight check

`gofmt` formatted the four changed Go files. One `go build -tags dev -o <temporary-directory>/klm-session-metrics.exe .` from `engine` succeeded; the temporary directory/binary was removed. No tests, full suites, review agents, commits or pushes. Build success does not validate native telemetry or UI behavior.

Follow-up: inspected the basic baseline/interim/final transitions without running a build or tests. Baseline resolution gates prompting; timeout clears correlation so late baseline replies cannot supply evidence. Interim requests can be superseded by a distinct final request; only its correlated response can complete accounting, and the final response wait expires after 2 s. Failed sends now also clear their request correlation so they cannot later be accepted as evidence. No other obvious introduced transition errors were found in this narrow inspection. Ran `gofmt` on `engine/interactive.go` and `engine/pi_interactive.go` only. The earlier build predates this follow-up; no build/test rerun, reviewers, commits or pushes.
